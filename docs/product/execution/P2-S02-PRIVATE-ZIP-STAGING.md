PackArchiveStager只接已通过可信根的不可变VerifiedManifest，创建专属NamedTempFile；按64KiB片段同时累计签名声明的准确长度/SHA256并写入私有文件，任何超长/写入/取消失败都使该stager不可复用。finish验证内容并sync、再次检查全局期限后才产生不可由JSON构造的StagedPackArchive。没有接收任意外部文件路径当成已验证字节，归档路径/可写句柄不对调用者暴露。真实下载流程仍需先做实际卷/空间/保留版本预检，再接此组件；本批不把低层字节接收叫作网络下载完成。

extract只能在指定parent中新建随机私有TempDir，不能传既有目标目录来覆盖。目录能力使用cap-std，所有文件create_new，目录/文件均按已校验相对路径操作；不会应用归档所有者/任意权限或创建链接。Unix源码只给普通文件0600、真实入口0700，Windows不设置可注入重解析属性；本机仅Windows测试，不冒称其他OS已验。返回ExtractedPack仍是可丢弃暂存，目录能力先关闭再由TempDir清理，没有活动版本/可调用状态。

支持范围是明确的简单ZIP32：Stored/Deflate，无SFX前缀、归档comment、ZIP64/分卷、加密或额外字段，TarGz明确不支持。条目名称必须原始UTF8与库解码名一致，再过S01便携ASCII路径规则；不使用mangled_name静默改名。目录必须空载荷，symlink和非普通类型拒绝，大小写别名/父路径文件冲突/缺失非空入口/签名最大条目及展开字节拒绝，全部索引校验后才新建输出目录。ZIP没有被解释成硬链接的创建路径；S01通用Hardlink元数据拒绝不冒充所有ZIP厂商额外链接格式都已测试，额外字段被整体拒绝。

元数据分配前置：只接受文件尾22字节的唯一简单EOCD，计数不超签名值且非ZIP64哨兵；中央目录不超4MiB且精确接到EOCD。目录中出现第二EOCD/ZIP64标记也拒绝（这是声明的严格profile限制，包含极少数CRC/额外数据恰有该字节序列的文件，发布方应重新打包）。ZIP库在坏目录后可能回溯更早footer，因此元数据阶段的GuardedReader把中央目录前的内容呈现为零；只有唯一受限目录解析成功且位置/条目数一致才开放真实压缩数据。可避免前置计数通过后，库从压缩体里假footer读取另一巨大计数。文件内容的相同字节序列在正常解压时仍保留，不改实际数据。

真实读取每64KiB核对条目实际输出和累计上限，CRC/解码错误拒绝。PackStageControl用共享取消标志和单调绝对期限（至多600秒）贯穿接收、ZIP元数据/压缩输入与输出；期限不会因新字节重置，也不在每份文件重开预算。同步磁盘调用可能在内核等待，本组件不宣称能中断该调用；sync完成后再复核控制，不能把过期或已取消结果交付为完成。
