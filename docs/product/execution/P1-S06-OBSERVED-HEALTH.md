# P1-S06 从真实网关调用记录健康（dev.11源码，未安装）

继续禁止电脑控制；本批没有窗口读取/截图/输入/激活/原生UI验收或用户安装更新。测试只用独占本机网关与受控上游，没有真实付费调用。

网关现在从实际完成的文本响应记录健康：非流式须有有效assistant文字与已知正常终止状态；SSE须经过校验、有文字且收到结束标记。普通最终回答的length/content_filter仍可作为有效协议响应，但不代表小队中间业务步骤成功；中间步骤仍执行SUP-005更严格的stop门槛。拒答、未知终止、无效角色、旧调用格式不获得新鲜成功，已知协议/传输/鉴权/限流等错误按枚举记录失败。用户取消的半截流不会刷新成功时间。

元数据由一个后台blocking worker写入，按供应商/模型/连接代次合并尚未处理的观测；队列/未确认集合受配置对象上限限制，不保存正文/密钥、不按请求无限创建线程。世代变更或模型移除会排除旧观察；旧配置晚到不会修改新连接。后台事务用共享维护锁与SQLite短IMMEDIATE事务检查代次，不持业务operation.lock，避免健康记录让用户保存配置遇到虚假的过期编辑冲突。关闭时停止处理队列，不让响应/取消等待健康落盘。

模型目录响应新增x-tagma-health-revision与x-tagma-health-writes-confirmed，后者只表示排队写入是否都已确认，不表示任何模型健康。写入失败不能标已确认，下一条对应已确认观察可恢复；全局自动选脑接线前仍需消费这项不确定状态及并发世代检查。first_cloud依旧未开放，不将当前观测切片称为A14完成。

验证：worker测试将1000次同目标观察合并、确认实际持久化且不增配置修订，再模拟SQLite写锁失败，验证未确认且旧失败状态保留，解锁后的新成功恢复。实际HTTP集成验证本机目录读取不会产生上游请求、完整回复持久化Ready、429记录Failed/RateLimited、取消不刷新成功时间。网关单元6、直接推理HTTP1、小队HTTP1及all-targets Clippy -D warnings通过，均无桌面操作。

剩余：目录探测、动态脑目标及first_cloud解析、健康未确认/非正常退出恢复、前端健康呈现及禁止期间未做的UI验收。业务权限、用量与撤销门槛也仍未完成。

复用现有target与缓存，无新环境/worktree/大下载或用户资料复制；Rust tempfile及worker/任务RAII回收独占测试资料。末次C47.78/D16.94GiB，D低于20GiB已提示；只做小范围编译/检查，未清理被拒绝目录、旧验收或用户安装，不能将并发盘变化当成自身净占用。
