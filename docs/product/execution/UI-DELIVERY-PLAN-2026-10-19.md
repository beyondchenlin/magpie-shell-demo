1. 用户可体验版本与入口。先核对用户入口、交接隔离候选与源码之间差异。以当前可用版本提供明确版本号、启动方式、功能位置和限制。对用户默认库/保留预览不得作为测试数据操作；可先交付任务专属可保留的体验入口。普通版本升级保护用户数据及未保存工作，避免为了可见变化覆盖运行中二进制。
2. P1 界面闭环。供应商添加/编辑/检测/模型目录 → 选择指定模型 → 流式对话/停止/失败后编辑重试 → 查看请求用量；市场入口 → 小队创建/成员与策略 → 发布 → 对话模型选择 → 实际执行/结果与步骤用量；网关接入信息和用量入口清晰。复用已通过的 dev.40 证据，只修实际缺失和体验阻碍。真实远端条件未具备时清楚标记，受控回复不能冒充真实模型。
3. ReachFlow 完整产品闭环。市场列表/详情/来源/权限/空间 → 安装/进度/取消/恢复 → 已安装状态 → 本地试跑 → 按服务既有授权调用与查询/取消 → 查看成果及位置 → 更新/卸载及影响提示/成果保留；接通队员路由和小队 pack 步骤。已存在安装接线或适配器先复核并复用。界面应面向普通用户，不把内部 review ID、摘要、幂等字段当作用户需要自行拼装的常规流程；尊重 ReachFlow 原服务确认契约，不能代确认。正式发行包、公钥、服务授权不足时定位具体外部条件，继续可独立完成的开发；不将测试签名根或 fixture 冒充正式队员，也不据此声称 P2 全通过。
4. P3 多入口。官方 CLI、Skill、MCP 复用同一核心，实际调通至少一个队员或小队；桌面提供可操作的接入说明、复制配置、状态与错误。外部应用配置写入需先展示目标和差异并遵守确认约束。
5. 独立 Pi 与会话切片。使用既有 Pi harness，模型经网关，提供持久会话、重命名/删除/恢复、真实工具授权；支持已验证格式的外部历史只读预览/导入，在 Tagma 新会话独立继续，永不回写原 Agent、不继承工具权限。不从零重造完整执行器，不整仓搬 PI-Desktop。

## 每批交付定义
每批选一个可以在界面走完的用户任务，同时打通所需前端、IPC、核心和结果展示。报告“入口 → 操作 → 可见结果”，及准确运行版本。
只有底层接口/测试的批次需说明直接支撑哪个下一用户动作，并尽快接入同一闭环；不得持续拆成只有底层进度的碎片。
保留必要测试与安全边界。先跑相关检查和 PRD 必须验收；已有通过证据可复用，未出现新失败/修改不重复全量测试或安装器专项。测试数量、提交数、文档长度不能作为产品交付量。
原生验证使用已授权隔离 Tagma 的 PrintWindow/UIA/SendInput；每批重新核验 owner、EXE/hash、唯一进程、窗口/焦点，按 AGENTS 原生规则操作。不能用浏览器、后台或 API 返回值代替真实界面成功。失败同法最多两次后换诊断思路，不盲点、不让用户代点。
状态明确区分“源码实现 / 构建候选 / 原生通过 / 已提供体验入口 / 真实服务与平台未验”；保留真实待办，不以隐藏/删除入口冒充完成。
每个可交付里程碑更新 EXECUTION-STATUS.md 和简短用户体验说明，附必要有界证据，继续下一项，无需等待每半小时监督放行。
