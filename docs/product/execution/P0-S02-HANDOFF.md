# P0-S02：独立网关、恢复与内部安装交接

2026-10-17；候选 `0.2.0-dev.3`；P0 仍未通过，release_blocked。前批提交 `7f5c5fb`。本页和 evidence/P0-S02.json 记录分层证据，不把 debug 包称为正式发行。

## 本批结果

网关为真正独立 Rust 程序，Rust 核心不依赖 Tauri。每配置目录独占实例锁；私有 Named Pipe 以当前用户 SID 限制访问，Unix 实现使用 mode 0600 的文件 socket（Unix 未实测）。身份绑定配置路径摘要、随机实例 ID、程序/schema/协议版本及请求 challenge；停止还需要只经继承 stdin 传入的随机所有权凭据。日志与管理 IPC 分开，没有 HTTP 管理操作。

受管子进程持有父生命周期 stdin；父退出触发网关 drain；独立实例关闭启动者 stdin 后继续运行。桌面连接已有实例不会取得停止权。固定端口占用不换端口、不杀占用程序。启动上限10秒；恢复最多3次/5分钟，延迟1/2/4秒；配置/权限/端口/身份错误不自动重试。退出只回收自身拥有的子进程。

网关只读不可变 SQLite 配置快照；有效版本由实例握手确认。定时核对恢复丢失通知。数据面尚未接推理，所有 HTTP 路径明确返回503/UNSUPPORTED_CAPABILITY，不能视为P1真实模型网关或正式鉴权已完成。

诊断通过受限命令预览后显式复制，只含版本、平台、状态、revision与枚举事件。日志统一上限20MiB×5，轮转有跨进程锁；记录类型不接受正文/Key/任意异常文本，导出仅解析白名单结构，最多64项。写入未确认会反映在诊断状态，不无限缓存。没有遥测。

## 用户新增黑窗要求

实际旧dev.2宿主和sidecar的PE均为Console(3)；宿主只在release启用windows_subsystem，导致内部debug安装同样可能出现黑窗。现两个程序在Windows所有构建默认GUI(2)，不是启动后再隐藏窗口。受管启动仍使用CREATE_NO_WINDOW。

- dev.3安装后PE均为GUI(2)：`P0-S02-console-{before,after}.json`。
- 安装后的原生驱动未使用windowsHide；从实际程序内部检查，宿主和sidecar的GetConsoleWindow均为空。启动/重启和父生命周期测试继续通过，stdin契约没有失效。
- Windows已安装应用启动器 `com.tagmaai.desktop` 正常启动，只新增Tagma主窗口，无控制台窗口；主界面和effective=0可访问性文本见 `P0-S02-normal-launch.json`。
- OS图形捕获仍超时，未声称拥有OS整窗/瞬时闪窗录像；PE、程序内附着状态和启动器窗口清单互相补证。后续目标设备仍需人工观感验收。
- 正常启动后尝试用输入helper验证关闭到托盘时，helper报foreground PID不可用，未宣称该用例通过。随后只读日志确认正常stop_requested/stopped，无测试进程遗留；未误杀未知进程。

## 监督问题闭环

SUP-001 / DATA-02：注入oneshot屏障后，旧成功晚到、旧失败晚到、Stopping被重写三个测试修复前全部失败。修复为完整加载/校验/提交串行化，提交前重查Stopping/取消，并防effective回退。三个用例通过；另增加阻塞凭据调用超时后保持一个工作线程的限额测试通过，避免取消等待后无限积累线程。启动加载有8秒预算，普通应用1.5秒预算。

SUP-002 / DATA-03/04：真实子进程在首次Connection::open后、schema提交前退出87，原实现在重启时IncompatibleVersion，复现失败。新实现先持久初始化intent和UUID专属暂存文件，完成事务、关闭SQLite、flush后，以no-replace发布最终数据库；Windows不使用REPLACE_EXISTING、不创建共享硬链接。恢复只处理可验证intent，未知schema0库或暂存内异常用户表均保留拒写。真实进程恢复、未知库字节不变、异常暂存保护、发布不覆盖四项通过。Windowsflush需可写句柄的问题在小范围测试中定位修复。未把任意schema0库删除或重建。

当前活跃实例遇旧版本manifest，先检查版本envelope，避免新增字段导致泛化成解析/重复启动错误；无活动锁的旧manifest不阻塞新启动。测试覆盖真实活动实例+旧envelope模拟，尚未建立所有历史二进制版本矩阵。
