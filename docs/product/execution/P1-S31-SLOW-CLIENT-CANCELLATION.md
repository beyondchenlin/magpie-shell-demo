# 慢客户端背压下的总预算与撤销

2026-10-18，接续7524b04；源码候选dev.16/config10/usage2。仅源文件/自有headless sidecar/loopback测试，用户安装dev.9与data/webview不动，不操作桌面。用户“不能自由拖拽”仍未修复/未验收，不能用本批后台结果替代。禁止电脑控制、真实上游/付费调用限制继续有效。

原来SSE源和用量包装器都由下游Body轮询。当真实客户端只读HTTP响应头、维持连接却不再读体，TCP发送缓存耗尽后，上游总期限与撤销选择器一起停止轮询。先失败证据slow-before：700ms配置到1500ms仍上游未关闭，持久记录Running/errorNone。上游产生4206592字节是自有服务已生成流量，不能解释为网关内存占用。

现在成功流的固定私有控制随Response交给独立任务：已准入请求各一任务，最多八个；单事件mpsc加单值terminal，不缓存整段结果、不释放下游名额。读取SSE与等待发送都选择撤销/退出/固定总期限；终止先drop真实上游，随后沿原唯一writer结算尝试与逻辑请求。保留已观察token与冲突转未知、失败不发DONE、存储结果未确认标识和明确恢复围栏。数据队列中的已准备事件先发，终止槽在队列耗尽后发一次；慢读者不能阻塞上游关闭或记账。下游Body drop由AbortOnDrop取消任务，沿原guard结算CLIENT_CANCELLED。正常完成也要先落账再暴露DONE，不把已准备/落账当作用户已收到。

上游idle仍以主动读取上游的间隔计算；因下游背压暂停读取时不虚称能判定上游是否空闲。本批独立总预算确保此时最终取消。HTTP请求体读期限、连接级完整限额及所有平台容量/延迟矩阵不是本批完成项。

第一遍自查需求与故障：

- 真实原始TCP、小接收缓存，仅读头后暂停1500ms：上游关闭，逻辑及一次尝试为REQUEST_BUDGET_EXCEEDED，token仍未知；同一socket恢复后有界部分正文加恰好一次错误，无DONE，状态在恢复前已经可读。
- 八个真实停读客户端，第九个429；私有revoke(true)确认后八上游关闭，八组逻辑/尝试均ACCESS_REVOKED。下游未释放仍429，断开后200，避免提前返还名额形成无界残留正文队列。
- 网关原26单元、文本/函数/小队/超时/用量/清除/撤销HTTP13通过，包括正常SSE token结算先于DONE、writer故障不发成功、客户端drop、TLS/header/idle/total、旧快照及SUP-007屏障；外部Windows curl8.13.0显式集成1通过，仍在假上游释放前读到首段、最后DONE/UTF8/函数及用量对应。加新2共42个不同用例通过，重复的慢客户端复验不重复计数。
