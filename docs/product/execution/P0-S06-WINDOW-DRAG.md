# dev.9 窗口拖动与用户安装

用户要求删除前面的安装版、重新安装最新版，随后指出窗口不能自由拖动。本批只修复窗口交互，保留 dev.8 恢复的 CIS 布局、共享样式和真实文本对话。

## 原因与修复

产品顶栏未声明 Tauri 拖动区域，主窗口 capability 也未允许 start_dragging。沿用顶栏的外观不能自动继承其他桌面框架的原生拖动行为。

顶栏与侧栏顶部现在使用当前 Tauri 2.12.4 自带的 deep 拖动区域；按钮、按钮中的文字/SVG、输入框等交互后代由 SDK 排除，不将整个页面变成拖动区域。主窗口仅新增 start-dragging 和 internal-toggle-maximize 权限，支持拖动及双击最大化/还原。未改公共 CIS 样式、窗口装饰、配置 schema 或 Rust 业务逻辑。

## 验证

TypeScript/Vite、修改组件 oxlint、驱动语法检查、chrome guard 和六 CSS guard 通过。最终原生独占 fixture 的八项检查通过：顶栏拖动原生命令获准、按钮/SVG 不触发拖动、导航仍可点击、侧栏顶部与面包屑的原生拖动调用、实际原生窗口双击最大化及还原、正常退出。见 evidence/P0-S06-window-dev9-final.json。

驱动通过观察真实 IPC fetch 的响应确认调用，无 mock bridge。前两轮驱动尝试给 SDK 的只读 invoke 属性赋值，观察钩子未生效，导致错误地判定没有调用；失败 JSON 均保留，没有据此修改或放宽产品行为。随后改用转发全部原始请求的 fetch 观察钩子，原生响应均成功。这里的合成 WebView 鼠标事件不证明真实物理鼠标位移；OS 截图仍 FrameArrived 超时，没有宣称实际自由拖动的人工观感验收通过。
