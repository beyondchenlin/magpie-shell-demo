## 明确的清除范围

仅支持已结束的完整UTC日范围，半开[start,end)，最多366日，不能包含未来日或当前未结束日。prepare_clear生成operation_id、范围、变更修订、清除代次、逻辑请求数、级联尝试数及日汇总桶数。它不写入/删除数据。当前不支持按供应商/错误等筛选删除，未来UI必须显示这是整个日期范围。

明细按逻辑请求开始时间选择，外键级联删除它的所有尝试；跨日尝试也计入预览。日汇总按各自开始日独立删除范围内桶，范围外桶保留。因此跨日尝试明细可能随请求一起删除，但其范围外日汇总保留。预览给出这三种数量，不能只显示日期让用户误解级联范围。没有删除正文、凭据、配置或会话数据的实现。

存在任何未终结请求/尝试、待恢复结果或用量降级时拒绝新清除；不会为了清除取消推理。全局变更修订随登记、结算、保留维护推进，任何改变使旧预览失效。提交在唯一writer的立即事务内重查空闲和完整预览，原子删除明细/日桶、更新保留起点、清除代次和最近回执；失败全部回滚。计数/修订/代次为精确十进制字符串，达到i64上限拒绝并回滚，不溢出或补零。

最近一次相同operation_id与完整plan的重试返回原持久回执，不再执行删除，重启及随后新增记录也一样。相同ID但不同范围/数量拒绝；旧回执与当前代次矛盾拒绝。更早回执被下一次清除取代后不能当作可重放删除计划。调用超时是否提交须由后续管理确认处理，本批尚未声称完成IPC超时闭环。

## 查询及页面缓存边界

请求/汇总游标带清除代次，事务内核对当前代次，清除前游标返回USAGE_CLEAR_CHANGED。读快照本身携带代次；实际WAL旧读事务在清除提交后仍可返回旧代次数据，这是SQLite快照行为，不能当作已取消。前端loader拒绝不同代次的明细/汇总混合，新代次详情会清掉旧列表。自身明确清除后的最低代次围栏和迟到IPC失效仍需下一批管理/UI接线，不能由本批代次字段冒称完成。

清除是逻辑删除，不做文件删除、VACUUM或安全擦除，不承诺立即释放物理空间。迁移备份与WAL可能仍保留历史元数据；不会自动从备份恢复已清除数据。备份保留策略及未来清除确认界面必须说明这个边界。
