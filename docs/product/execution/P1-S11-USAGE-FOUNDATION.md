# 独立用量库基础（源码，尚未接网关）

2026-10-18。延续已授权的非 UI 开发；本批新增 tagma-core::usage，**尚未接入网关派发、流生命周期、私有 IPC 或用量界面**。不能把核心存储测试当作“上游派发前已登记”的 HTTP 验收。A16/A28/P1继续未通过。用户安装仍dev.9，拖动仍未通过，没有控制桌面、更新安装、读取真实凭据或创建用户用量库。

## 已实现的基础

- usage.sqlite3 与 config.sqlite3 分开；专属单 writer 文件锁、已知 application_id/schema/对象/列校验。既有文件先只读识别，未知文件不初始化或覆盖。自有原子发布的初始化 intent 支持建库前和 DDL 提交后进程中断恢复，拒绝重解析路径及未知 intent。
- 明确区分一个逻辑请求和最多16次顺序上游尝试，最多8个在途逻辑请求。begin_request/begin_attempt 均提交持久开始记录后返回；开始写入失败进入 degraded 并拒绝后续登记。此处是存储契约，网关尚未调用它。
- 结束结果与 UTC 日汇总在同一事务内保存，重复相同结果不重复计数，矛盾结果拒绝。未知 token 保持 NULL，汇总同时保留已知部分与未知数量；逻辑请求只有所有尝试提供相应 token 时才有相应总数。请求正文/响应正文/头/凭据无字段；错误只接受稳定网关代码。
- 结果失败保留有限恢复队列（硬上限32；8请求与8在途尝试的故障测试实际16项）；有待恢复结果时拒绝新登记。显式恢复按顺序幂等提交，且 checkpoint 成功才清除 degraded；未提供无限自动重试。超过队列上限仍返回失败并保留原开始记录，后续重启体现结果未知。
- 重启将未终结请求及尝试标记 interrupted，缺失用量保持未知。结束时已持久汇总，再按30天清理明细、12个日历月清理日汇总，持久记录明细起始时刻。256MiB是主库目标上限；WAL有独立16MiB登记围栏、自动checkpoint及2MiB journal_size_limit，连接缓存2MiB。容量压力先删已有日汇总的旧明细，不能回收时失败关闭；这不是对整个目录物理占用的256MiB承诺。

## 两轮自查

同一执行者两轮，非独立审计。

1. 检查结果失败后的顺序：补后续逻辑结果排队，防止尝试未落盘导致逻辑结果丢失；补幂等逻辑 token 总和、顺序时间约束、checkpoint busy 不清除降级、WAL元信息读取错误不冒充0、日汇总整数溢出拒绝。SQLite u64读写类型错误在首轮编译暴露，已改显式有界转换，失败原日志保留。
2. 检查未知文件及证明质量：既有数据库先只读验证完整形状，再开启写模式；初始化 intent 读取限制字节数；同 application_id 的未知对象库也逐字节保留。隐私断言原先使用了不匹配的固定窗口，已改用被拒绝文本的实际字节长度，最终完整lib检查包含修正。补真实 exit90，而非仅正常 drop 后重开；补真正 SQLITE_FULL，小样本不填满磁盘。
