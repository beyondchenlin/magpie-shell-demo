# SUP-006：健康有效期从观测时刻开始

修复前用注入时钟与可控worker精确复现：t0=1000时成功入队，worker被短时gate阻止；时钟直接推进到301001后释放，旧实现把成功时间写成301001，Ready=true且纯first_cloud选择器选中了它。没有真实sleep五分钟，也没有填满队列。原始失败见evidence/P1-S06-SUP006-before.txt。

现于响应完成/失败的observe入口、获取队列锁之前捕获时间，随合并项保存；worker只提交这个原始观测时间，绝不在落盘时重打时间。目录与推理为两个独立槽，目录事件不会覆盖推理结果；每槽只接受较新事件，同毫秒一律失败优先。多种失败同毫秒按固定保守优先级选取，旧成功不能清除较新/同毫秒失败，旧失败不能覆盖较新成功。数据库合并也执行相同规则，不依赖线程到达顺序。

修复后同一延迟场景持久时间为1000，在301001时Stale、Ready=false、selected=false；after与扩展final原始结果均保留。核心健康8项覆盖TTL边界、排序/代次、同毫秒双顺序、过时事件、目录分离和未知运行状态；gateway健康3项覆盖受控延迟、合并、写失败未确认与恢复。原有真实HTTP取消不刷新成功时间、直接模型/小队与生命周期回归继续通过。见evidence/P1-S06-SUP006-{after,core,final,regression}.txt。

此处first_cloud是纯选择器验证，尚未开放小队自动脑的发布和网关解析；默认App回退及完整A14没有因此通过。新增可信Rust观测时间入口不作为前端IPC开放，用户不能通过页面伪造健康时间。

电脑控制一直禁止，仅非UI本机fixture/时钟/HTTP测试。所有原始结果体积为KB级，保留在版本控制中；没有付费调用、凭据读取、真实sleep五分钟、新环境/worktree或用户安装变更。
