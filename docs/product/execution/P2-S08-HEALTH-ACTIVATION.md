# P2 健康检查与活动版本

2026-10-19，接续 dev.40 / P1-S33。dev.40 隔离原生实例继续保留，本批未将新运行时装进它，也没有重跑安装器专项。所有调度保持 PAUSED。

## 已实现

- Rust 运行时从准备目录重新验证配置身份、当前信任根、签名、期限与文件树，精确匹配用户批准的清单 SHA256；执行当前平台原生入口及固定 argv，不经 shell。
- 一次进程接收一个有界 JSON 请求，关闭 stdin 后返回一个有界 JSON 结果。健康检查与固定素材试跑分开；请求 UUID、队员 ID、版本、协议和结果类型全部匹配才成功。错误、崩溃、输出超限不转换成成功。
- 单执行器并发为 1，不排无限队列；签名/文件验证工作也占有许可。超时或取消杀死并等待直接子进程退出。子进程环境清空，仅 Windows SystemRoot 保留；不传凭据、代理、PATH、用户目录或宿主配置。stderr 只做容量限制，不返回原始内容。
- 健康成功后再次核验准备目录，再按 expected_revision 提交现有配置事务。配置身份相异、清单变化、失效或修订冲突保留原活动版本。同一版本不能替换成另一份准备目录/清单。
- 配置保存不可变版本记录及活动指针。调用从一次快照解析版本，停用阻止后续解析；保留运行文件，不删除用户成果。停用不等于完整卸载。
- schema 10→11 使用原迁移和备份机制，保护新字段不被旧写入器丢弃；历史 JSON 不改写。TypeScript DTO 由 Rust 生成。

## 验证与边界

实际执行 `pack_protocol_fixture.exe` 的 6 项定向测试通过（显式 `--ignored` 启用，不把默认忽略计为通过）：健康/中文试跑、批准摘要及载荷变化拒绝、错误身份/崩溃/输出界限、超时/取消/忙态/直接子进程回收、健康后登记/恢复/停用、健康失败保持空安装记录。配置设施为临时目录，凭据接口读写均会触发测试失败，实际没有访问真实凭据。

独立 schema10→11 用例通过：原供应商、修订、配置 UUID、历史 JSON 和 schema10 备份保留。core/runtime 全 targets Clippy `-D warnings`、DTO 生成和 TypeScript 检查通过；ts-rs 对 deny_unknown_fields 的既有解析提示不代表 serde 放宽输入。

这是核心及实际子进程测试，**不是新的原生桌面验收，也不是真实 ReachFlow**。测试发行者 `tagma-owned-test` 及私钥只存在测试构造中，正式信任库仍默认拒绝所有发行者。

尚未交付：下载/批准/安装的桌面完整接线、持久任务与退出协调、真实 ReachFlow 适配器、队员路由、更新/卸载引用与在途任务流程、进程树及内存硬限制。当前权限声明不是操作系统沙箱；不能把清空环境解释为禁止网络/文件系统访问，也不能承诺直接子进程退出必定回收所有后代。因此本批运行 API 尚未向外部模型或用户安装入口开放。

只读检查 `D:/demo1/reachflow` 的启动源码、HTTP 路由和契约目录：现有程序是服务运行时，未找到 Tagma stdio 队员适配器。适配器属于待开发代码；正式签名发行包/发行公钥和经授权的服务、预算、平台/浏览器条件属于独立环境条件。没有读取该仓库真实配置、启动服务或执行采集。

## 可复核运行方式

复用原 target 与 Cargo.lock，先构建本仓库测试 example，核对本批 fixture identity，再显式设置 TAGMA_PACK_FIXTURE 为该 EXE 路径、TAGMA_PACK_TEST_SECRET 为合成 canary。运行 `cargo test -p tagma-runtime --test pack_execution --locked --offline -- --ignored --nocapture`。示例二进制不随产品分发。

输入 text ≤16KiB，stdout ≤128KiB，返回文本 ≤64KiB，stderr ≤64KiB；准备验证最长10秒，健康及试跑期限取签名清单。调用仅支持 ping/local_sample，未定义真实采集授权请求。
