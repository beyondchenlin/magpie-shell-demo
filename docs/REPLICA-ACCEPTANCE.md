# Magpie 复刻阶段验收标准 v1.0

状态：验收口径草案已落盘；暂停新增 UI 修改，先审阅本标准。制定日期：2026-10-16。

## 1. 本阶段交付和边界

交付一个以假数据运行、可在本地与 PR 临时预览中检查的 Magpie 视觉/交互复刻，并将共用规则沉淀为 CIS 与组件。**修复过、能构建、CSS 同源，均不等于最终验收通过。**

范围固定为当前已接线内容：

- 六个主页面：Agent、供应商、路由、网关、用量、插件。
- 设置七个分区：常规、额度、网络与共享、模型、隐私、同步与备份、关于。
- 已接线的 Library 四个页签，以及用量中的 Sessions / Context：检验现有 mock UI 的排版和交互，不继续扩业务。
- 本文 C1–C4 指定的公共控件与弹层。页面中的相同控件遵守同一配方。

本阶段不实现真实 OAuth、订阅计费、Key 落盘、真实网关代理、原生系统字体枚举、真实插件执行或 Tagma/PackGate 新功能；不打 exe/portable，不合并 main，不发布生产环境。Mac 系统专属行为另列专项，不以缺少 Mac 点录无限延长本次 Windows/Web 壳验收，也不声称这些行为已验收。

**清单外的新需求先记录，不边改边扩大范围。** 若它直接破坏下列既定路径，归入相应验收项；否则作为下一阶段候选。不能通过事后改成“不适用”来消除失败。

## 3. 测试条件与判定规则

### 3.1 固定环境

主验收使用中文、浅色、110% 文字大小；深色按 B4 的固定页面集合复测。参考图和候选必须使用相同平台、内容区域尺寸、主题、字体和字号再比较。

固定 Web 视口：

| 场景 | 视口（浏览器 CSS px） | 检查目的 |
| --- | --- | --- |
| 宽桌面 | 1364 × 941 | 侧栏、设置和网关主要外观 |
| 中桌面 | 1048 × 900 | 导航折叠与浮层边界 |
| 紧凑桌面 | 900 × 900 | 顶部导航与紧凑窗口 |
| 窄屏兼容 | 390 × 844 | 无横向溢出、菜单/弹窗可操作；不冒充原生桌面金标 |

保留既有预览尺寸配方：紧凑最大 752×652、宽窗最大 1100×720，按视口和 zoom 约束；折叠导航不能改变外框大小。1023/1024px 只补验导航断点，不额外扩展全页测试矩阵。

用独立 mock 数据或明确 URL fixture；记录并恢复测试改动的偏好，不清空用户存储。真实密钥、账号、系统设置不用于验收。

### 3.2 外观

- 同一控件的颜色、字体族、字号、字重、行高、圆角、边框、控件高度、内外间距采用同一 CIS 配方；控件不同用途的原生差异保留。
- 同条件下，关键边界和对齐偏差不超过 **1 CSS px**；文字换行、列宽与控件排列一致。不得以缩放图片或更换字号掩盖差异。
- 有对应金标的状态做并排/叠图核对；动态文本、时间和 mock 数值可遮罩，按钮、边界、选中态和布局不能遮罩。
- 系统抗锯齿差异可以说明，不能用来豁免错误字体、字号、行高、缺图、错位、截断和溢出。
- 没有对应图的状态记录为“源码核对”，不能写成“像素验收通过”；最终四个重点问题必须有可复查的候选截图或录屏。

### 3.3 动效与操作

- 折叠使用固定参考的 **320ms / cubic-bezier(.42,0,.58,1)**。参数相同只是源码检查的一项，不能证明顺滑。
- 正常前台标签页、常规 60Hz 环境下，折叠/展开 **3 轮，每轮 10 次**；每轮无闪白、外框跳动、冻结和选中错位。记录帧间隔/性能轨迹：P95 帧间隔不超过 33.4ms，无 100ms 及以上停顿，无归因于本次切换的 50ms 以上主线程长任务。后台标签页节流数据无效；未采集不能标通过。
- 菜单第一次打开即正确出现；点击结果、正文、当前选中状态同步。不能依赖“再点另一个页面就恢复”。
- 键盘、鼠标、焦点、关闭方式按参考中对应的控件配方验证；不把不同菜单强行改成同一种交互。
- 复制不仅检查图标变化，还须核对剪贴板内容；mock 动作检查可见状态及数据恢复，不能宣称真实后端成功。

## 5. 证据和失败处理

每条记录包含：验收 ID、候选 SHA、环境、步骤、预期、实际、截图/录屏/性能数据、结果、复验记录。不同候选的材料不能拼成一个“全部通过”。

已有证据可复用：`interactions/web-cis-0.1.191/`、`interactions/web-frame-0.1.193/`、`interactions/web-cis-0.1.194/`、`interactions/web-cis-0.1.195/`。其中 v195 是工作稿证据，须绑定提交后再核实。截图不能代替复制内容、持久状态或性能验证。

失败时先定位到一个 ID，再做最小修复，复验该项与直接受影响项。不得为了“看起来更统一”顺便改下一批无关页面，不按版本号递增来衡量进度。进度报告只报：通过/未通过/待验数量、当前缺陷 ID、剩余证据。

## 6. 明确结束条件

**29项全部通过 + 范围内0个未关闭差异 + 最终同一候选可复查 + 用户对四个重点问题的一次观感确认。**

四个重点问题为：折叠是否顺滑、折叠后选中是否正确、设置是否统一、网关是否整齐。它们有一项未通过，就不能称本阶段完成。

到达上述条件即停止本阶段修改，交付 PR、临时预览、验收报告与 CIS；后续新想法另开范围。缺少某项证据就明确记“待验”，不能靠继续无边界改代码来替代，也不能提前宣称全量 1:1。
