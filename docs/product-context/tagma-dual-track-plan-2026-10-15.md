## 3. 交点（两轨如何汇合）

| 交点 | Track A 提供 | Track B 提供 | 汇合结果 |
|------|--------------|--------------|----------|
| **默认三页 IA** | 对话 / 供应商 / 队员市场 + 二层清单 | 视觉上如何排、组件怎么长 | 产品壳按三页落地；Magpie 多出来的侧栏项进二层，不平行铺 |
| **供应商页** | 能力来自 CC Switch（C1–C4） | Magpie Providers 视觉/表单范式 | 能力跟 CC Switch；观感可靠 Magpie token |
| **队员市场** | LocalAI Gallery 心智（装/试跑/体积） | 卡片密度、空态、安装进度样式 | 市场页有统一卡片规范 |
| **组合小队** | Magpie 路由组升级为含队员的配方 | 编辑器布局、节点样式 | 入口在市场；完整 CRUD 二层 |
| **路由图 / 用量** | 二层；P1 简用量 | Magpie 路由页/用量页 1:1 可当参照或素材 | 产品不强制 P0 做完 1:1 |
| **加新按钮** | 先查融合表：L0/L1/L2/Pi/否 | 查 CIS：颜色、字号、主/次按钮、位置 | **先 A 定性，再 B 定形** |
| **术语** | 队员 / `tagma/` / 薄 Skill / Pack | UI 文案与徽章 | 两侧用同一术语表（PRD §3） |

**决策顺序（强制）：**  
`能力落层（A）→ 是否进默认三页 → 再 CIS 画法（B）→ 再写代码。`  
禁止「先画了第四个主导航再回头改融合表」。

## 4. Track B 应交付的 CIS 最低清单（A 侧期望 · 由 B 落地）

> 下列由 **Track B 代理**写进 CIS；此处只列期望，便于汇合。

1. **色板 / 字体 / 间距**：管理面对标 Magpie（灰白 + 靛紫）；对话面暖底规则（若沿用 agent-ui 子集）。  
2. **导航**：默认三页 vs 二层抽屉/子路由的写法；禁止无评审新增顶层项。  
3. **卡片**：供应商卡、队员卡、小队卡 —— 状态（启用/安装中/错误）统一。  
4. **主/次/危险按钮**与空态、加载、Toast。  
5. **表单**：Key、Base URL、slug（ascii）校验提示样式。  
6. **「加一个功能」检查表**：改哪一页、是否二层、文案术语、是否需要新徽章（Pack vs Skill）。
