## 1. 背景与目标

### 1.1 问题

本地 Agent（Claude Code、Codex、Cursor、豆包工作等）各自管模型与 Key，能力割裂：

1. **入口分散**：故障转移、用量、意图分流难统一。
2. **重能力进不来**：TTS / ASR / 字幕 / 剪辑 / 爬虫等本机产能，无法作为「选模型」一等公民出现。
3. **环境门槛高**：普通人配 Python、爬虫、FFmpeg 成本高；需要二进制安装 + 按需下重模块。
4. **壳与网关割裂**：CC Switch 擅长多 App 配置；Magpie 擅长路由；LocalAI 擅长按需装单元；New API 擅长渠道/用量——缺一体、且要轻的个人产品。

### 1.2 产品一句话

**Tagma** = 轻量 Agent 入口（接任意 API，对标 CC Switch）+ 路由网关（对标 Magpie；组合小队出现在选模型列表）+ 按需本地专家单元（学 LocalAI「小核心、用到再装」；**不做**本机大模型服务器，**不 fork / 内嵌 LocalAI**）+ **长线内置 Pi 系 Agent**（打开即可聊；可自然语言管本机 Tagma）。

用户隐喻：**产品层迷你多模态混合专家**——一个出口，网关把流量打到各「队员」（重型模块）与可选大模型脑。

### 1.3 地基优先（执行纪律）

> **先打牢地基，再堆插件式队员。** 内容队员队列不是近期关键路径。

**地基（必须按序做透）=**

| 地基块 | 对应层 | 含义 |
|--------|--------|------|
| 壳主路径 | L0 | 默认三页可用；按 App 管供应商 / 薄 Skill / MCP |
| 真网关 + 组合 + 用量 | L1 | OpenAI 兼容 `/v1`；`tagma/` 自有 id；组合小队进 models；简易用量 |
| 运行时契约 + **一个**验证队员 | L2 | Pack manifest / 安装 / 子进程隔离；**仅 ReachFlow** 证明「装上即可路由」 |

**地基打牢之后：** 其余队员（TTS、ASR、剪辑、文档、财务…）= **插件目录（backlog）**——与主程序松耦合，按同一契约独立发包；**不**占用地基阶段的并行带宽，**不**作为阻塞开工的开放决策。

纪律一句话：**先个人桌面；先壳 → 网关 → 运行时契约 → ReachFlow 验证；禁止地基未稳就铺一长串内容 Pack 或 Docker。**

**独立长线（不挡地基）：** 内置 Pi 系 Agent（§5.5）与地基 **并行规划、分期落地**——P0 对话可假；真 Agent 循环放在 **P1 网关稳了之后**；**禁止**为做内置 Agent 推迟壳/网关/ReachFlow。

### 1.4 目标（可验收）

| # | 目标 | 验收信号 |
|---|------|----------|
| G1 | 自研重写，非二开 | Tauri 2 + Rust + React；仓库自有；不 fork CC Switch / Magpie / LocalAI |
| G2 | 抢「选模型」入口 | Agent 将 Base URL 指到本机 Tagma 后，`/v1/models` 同时出现：上游云模型名、以及 `tagma/…`（官方队员 / 用户小队） |
| G3 | 组合小队可用 | 用户配置队员 + 可选 LLM → 导出 API id 为 `tagma/<ascii_slug>`（展示名可中文）→ Agent 可选中并跑通一轮 |
| G4 | 重型模块按需热加载 | 市场安装后成为路由目标；默认安装包**不含**大参数本地对话模型 |
| G5 | 个人版优先、轻核心 | Win/Mac/Linux **单一原生安装包**（壳+网关同装），**不依赖 Docker**；核心体积以数十～数百 MB 为理想（不硬卡上限） |
| G6 | 封闭 Agent 可桥接 | 不能改 base_url 的 Agent（如豆包工作）经 **Skill** 与/或 **MCP** 桥调用 Tagma 能力 |
| G7 | 能力三入口对等（YoVoice 式） | 同一套运行时（网关 + 已装队员）可被 **Skill（SKILL.md）**、**MCP server**、**CLI（`tagma`）** 对等调用；桌面壳是管理面，**不是**唯一入口。OpenAI 兼容 `/v1` 仍是可改 base_url 的 Agent 的主路径 |
| G8 | 内置 Pi 系 Agent（长线） | 打开 Tagma 即可对话；脑经本机网关（云 API / 以后小队）；可经 **对内控制 MCP** 用人话装/卸队员、改供应商、看用量、组小队（需确认门）；**不**为内置 Agent 再嵌大本地 LLM |

### 1.5 目的 → 方法 → 怎么做

| 目的 | 方法 | 怎么做 |
|------|------|--------|
| 普通人用本机专家能力 | 二进制 + 按需队员 | 个人版 Tauri 安装包；重能力市场下载 |
| Agent 只改一处入口 | OpenAI 兼容网关 | 本机 `/v1`；**仅 Tagma 自有模型 id** 使用 `tagma/` 前缀锁定品牌（云模型保留上游原名，见 §7） |
| 组合像组特战队 | 配方 → 对外一名 | 后台拼队员 + 脑 → 写入 `/v1/models` |
| 学四套软件能力、不叠四套 UI | L0/L1/L2 分层 | **产品 IA 冻结为默认三页**；路由与用量进二层（Magpie 1:1 外观 demo ≠ 产品 P0 阻塞项，见 §6） |
| 公司以后一台服务器 | 同一网关、另一发行 | 个人先做；服务器版 Docker Compose 后置 |
| Agent / 终端多种用法 | 同一运行时多入口 | `/v1` + Skill + MCP + `tagma` CLI；壳只管配置与市场 |
| 打开 Tagma 就能当 Agent 用 | 内置 Pi 系 harness（长线） | 对话页升级为内置 Agent；对内控制 MCP；脑走网关 |

## 2. 用户与场景

### 2.1 用户

| 角色 | 诉求 |
|------|------|
| 个人重度 Agent 用户 | 多 CLI/IDE 共用供应商、路由、用量；选 `tagma/…` 即用组合能力 |
| **只用 Tagma 的用户（长线）** | 打开壳即用内置 Pi 系 Agent 聊天 + 用人话管本机；不必另装 Codex / Claude Code（愿景；近不挡地基） |
| **仅用网关的用户** | 不打开内置对话也可以：只要本机网关在跑，外部 Agent 指到 `/v1` 即可（**不要求**使用内置 Agent） |
| 内容 / 音视频制作者 | 本机 TTS/ASR/字幕/剪辑当「队员」，不另配环境 |
| 调研 / 运营 | ReachFlow 类爬虫队员：装上就能让 AI 调参跑，不自己配反爬环境 |
| 垂直场景用户（财务等） | 选一个小队/队员 ≈ 预置工作流与资料已配好 |
| 封闭 Agent 用户 | 豆包工作等：装一条 Skill/MCP 桥进 Tagma |
| 公司运维（以后） | 一台机器 Docker 起服务，局域网多人打 API |

### 2.2 核心场景

1. **换入口**：Claude Code / Codex 等把 Base URL 指到 `http://127.0.0.1:<port>/v1`。Key 行为见 §10.1（个人默认鉴权关，客户端可填任意非空占位）。模型列表见上游云模型名与 `tagma/…`。
2. **组特战队**：从队员市场或二层「组合小队」进入配方编辑，把剪辑 + 爬取 + 财务 + 某个 LLM 拼成配方；**展示名**「抖音研报」、**API id** `tagma/douyin-report` → 列表出现该 id。
3. **不选手动 LLM**：脑默认走 `first_cloud`（排序规则见 §7.3）；可选按需「轻量 Local Brain」队员；**安装包不预置大模型**。
4. **装队员即用**：市场装 ReachFlow → 路由可达 → 外部 Agent 或（可选）内置 Agent 可调。
5. **壳侧运维**：按 App 管供应商（CC Switch 习惯）；网关挂了也能改配置。
6. **Skill / MCP 桥**：封闭 Agent 装官方 Tagma Skill 或连 MCP → 间接调用队员与组合。
7. **CLI**：终端执行 `tagma …`（对本机网关），与 Skill/MCP 调同一运行时；不必开桌面壳。
8. **内置 Agent（长线）**：对话页 = Pi 系 harness；用人话「装爬虫队员 / 换供应商」→ 走对内控制 MCP（确认门）；对外仍是普通 Agent（Skill/MCP/CLI 可用）。
9. **局域网（以后）**：服务器版 Docker；监听可绑局域网；按 Key 记用量。
10. **网关-only**：用户可关闭或不使用内置 Agent 页；Tagma 仍作为纯本地 API 入口工作。

## 5. 架构与发行

### 5.1 三层（能力融合，不是四个 UI 叠罗汉）

```
┌──────────────────────────────────────────────────────────┐
│ L0 壳（CC Switch）                                         │
│ 按 App：供应商 / 薄 Skill / MCP / 提示词；网关挂了也能改配置 │
└───────────────────────────┬──────────────────────────────┘
                            │
┌───────────────────────────▼──────────────────────────────┐
│ L1 网关（Magpie + New API 用量味）                         │
│ OpenAI 兼容 · 路由 · 组合小队 · 渠道 · 流量统计              │
│ GET /v1/models → 云模型(上游名) | tagma/官方队员 | tagma/用户小队 │
└─────────────┬─────────────────────────────┬──────────────┘
              │                             │
         Cloud LLM APIs              L2 队员运行时
              │                    （LocalAI 式按需单元）
              │                    契约 + ReachFlow 验证；其余插件化
              │                             │
              └──────────┬──────────────────┘
                         ▼
              （可选→长线）内置 Agent：Pi 系 harness
              P0 可假 / 过渡壳；脑走网关；对内控制 MCP
              网关-only 用户可不启用
```

说明：**内置 Agent / 对话是便利面，不是使用 `/v1` 的前提。** 外部 Agent 直连网关即可完成 G2/G3 类验收。长线形态见 §5.5。

### 5.2 两版发行

```
                    ┌─────────────┐
                    │ 同一套核心   │
                    │ 网关 + 队员  │

   重队员仅桌面跑                       …
   国内：原生包 + CDN                   国内：CN 镜像仓库
           │
           ▼
   Web：壳预览 only（不跑重队员）
```

### 5.3 网关进程形态（已冻结：sidecar）

**已定：壳与网关分开（两个进程），同一安装包（一个包分两个）。**

| 项 | 冻结 |
|----|------|
| 进程模型 | **Sidecar**：独立二进制 `tagma-gateway`（或等价名）；壳启动时拉起/监管 |
| 安装面 | **一个安装包**内含壳 + 网关（及后续 `tagma` CLI）；禁止「只装壳、网关另下一套安装器」 |
| 用户感知 | **开壳 = 网关可用**（默认同启；允许设置里关网关）；用户不必理解双进程 |
| 对照 | 学 OpenClaw / Hermes「壳与网关可分开」；对外仍是一份安装、一次打开 |
| 与队员隔离 | 队员一律子进程/sidecar（另一层）；勿与「网关 sidecar」混称 |

| | 曾考虑：内嵌 | **已选：Sidecar** |
|--|-------------|-------------------|
| 含义 | 网关跑在 Tauri/壳进程内 | 壳拉起独立网关进程 |
| 利 | 安装面更「单进程」 | 网关崩了壳往往仍可改供应商；启停/端口更清晰 |
| 弊 | 网关故障可能拖垮窗口 | 多二进制、端口、启停（由安装包与壳编排消化） |

P0 假数据壳仍可不启真网关；**P1 真网关按 sidecar 实现。**

### 5.4 客户端入口（对等面，非仅桌面）

| 入口 | 谁用 | 与运行时关系 |
|------|------|--------------|
| **桌面壳** | 配供应商、装队员、组小队、看用量 | 管理面；可选内置对话 |
| **OpenAI `/v1`** | 能改 base_url 的 Agent / IDE | 主程序化路径（G2/G3） |
| **Skill（SKILL.md）** | 封闭 Agent、工作流装配 | 桥进同一网关/队员 |
| **MCP server** | 支持 MCP 的宿主 | 桥进同一网关/队员 |
| **`tagma` CLI** | 终端用户、脚本、CI 本地调试 | 对本机网关的一等公民入口 |

**冻结：** Skill · MCP · CLI 是 **对等三入口**（学 YoVoice「同一能力多种用法」）；桌面不是唯一调用面。交付见 §15 P3；薄 CLI 若实现成本低可提前到 P1 之后随网关附带。

### 5.5 内置 Pi 系 Agent（长线冻结 · 不挡地基）

**已定方向（独立发展线）：** 把 **Pi 系 Agent harness** 融入 Tagma——学 LocalAI「内置可用自然语言管本机」的味道，以及 earendil-works/pi 一类 **薄 harness + 工具 + MCP**；**不是**把 PI-Desktop（Electron 整壳）搬进来。

| 项 | 冻结 |
|----|------|
| 产品位置 | 默认三页之 **「对话」** 长线升级为 **内置 Agent**（非又一块运维页） |
| 脑 | **一律经本机网关**（云 API / 以后小队）；**不**为内置 Agent 再嵌大参数本地对话模型 |
| 对内 | 官方 **Tagma 控制 MCP / 特权工具**：装卸队员、改供应商、看用量、组小队等；**仅本机内置 Agent**；敏感操作 **确认门** |
| 对外 | 仍是普通 Agent：可用已冻结的 Skill · MCP · CLI；长远逐步吃满 Pi 插件/扩展生态 |
| 壳技术 | 继续 **Tauri**；只借 Pi 的 **agent-core / 工具协议**，**禁止**整仓 fork PI-Desktop Electron |
| 与地基关系 | **并行规划、不挡地基**；P0 对话可假数据；**真 Agent 循环**在网关稳后（建议 ≥P1，细节随实现文档） |
| 愿景边界 | 「用户每天打开 Tagma 而非 Codex / 豆包工作」= **愿景**；**不是**近期关键路径，不与壳→网关→ReachFlow 抢带宽 |

**与「自研第二套执行器」关系：** 优先接入既有 Pi 系 harness / 协议，避免从零再写一套 agent loop；过渡期可用轻量对话壳，目标态以 Pi 系为准。

## 6. 信息架构（渐进披露）

### 6.1 产品 IA（已冻结）

**默认三页（用户每天碰）——产品 P0 以这三页为准：**

1. **对话 / 内置 Agent** — 可选便利面；经网关；**P0 可假** → 长线接 **Pi 系 harness** + 对内控制 MCP（§5.5）。网关-only 用户可忽略本页。  
2. **供应商** — 按 App 的 Provider 卡片（CC Switch 主路径）  
3. **队员市场** — 浏览 / 安装 / 启用 / 试跑；入口含 **「组合小队」**（见 §6.2）；徽章区分官方队员与用户小队  

**二层（需要时进）：**

- **组合小队**（配方 CRUD）— 完整编辑器；亦可从队员市场快捷入口进入  
- 路由图 / 网关状态  
- 用量  
- MCP · Skills · 提示词 · 会话 · 授权  
- 设置 · 应用  

**不做**：侧栏平铺 LocalAI 式 Backends / Swarm / P2P / Agent Hub 二十项。

### 6.2 组合小队从哪进

| 阶段 | 入口 |
|------|------|
| **P0** | 队员市场页提供「组合小队」卡片/按钮；点开可为**假数据/只读示意**或简易表单（不要求真通网关） |
| **P1+** | 同上快捷入口 + 二层「组合小队」完整 CRUD；保存后写入真实 `/v1/models` |

- **Magpie 管理面 1:1 视觉/点录**：外观参考与历史壳 demo，**不是** Tagma 产品 P0 的阻塞项；可与产品实现分离跟踪，可暂停。

## 7. 模型 ID 与组合配方

### 7.1 ID 规则（云 vs Tagma 自有）

| 类型 | 对外 API id | 对内 id（可选） | 前缀 |
|------|-------------|-----------------|------|
| 云渠道模型 | **上游原名**，如 `deepseek-chat` | `provider:<name>/<model>` | **无** `tagma/` |
| 官方队员 | `tagma/reachflow` | `pack:reachflow` | 有 |
| 用户小队 | `tagma/<ascii_slug>[@版本]` | `composite:u_<id>` | 有 |
| 轻量本机脑（可选 Pack） | `tagma/local-brain` | `pack:local-brain` | 有 |

**澄清（消除「模型 id 统一 tagma/」歧义）：**

- `tagma/` **只**用于 Tagma 拥有的实体（官方队员、用户组合小队、官方可选 Pack）。  
- 云模型**永远**保留上游 id，便于 Agent / 文档 / 账单对齐。  
- `/v1/models` 是**混合列表**：上游名 + `tagma/…` 并存。

### 7.2 短名、展示名、官方保留

1. **API slug 必须 ascii**：`[a-z0-9]([a-z0-9-]*[a-z0-9])?`，长度建议 2–64；禁止空格与非 ascii。例：`douyin-report`。  
2. **display_name 可中文**：例「抖音研报」；仅 UI / 卡片展示，**不**写入 Agent 可能持久化的 model id。  
3. **前缀 `tagma/` 系统写入，UI 不可删**；用户只编 slug（或从展示名自动生成 ascii 候选并允许改）。  
4. **官方保留 slug（用户不可占用/覆盖）**：至少包括 `reachflow`、`local-brain`；后续官方队员上架时同步加入保留表（如 `tts-zh`、`asr-subtitle`、`ffmpeg-edit` 等）。用户若输入保留名 → 拒绝或强制改名。  
5. **用户之间重名**：本机/账号下自动后缀 `@2`、`@3`…（作用于完整 public id）。  
6. **已发布 id 勿随意改义**：Agent 会写死 model id；改配方则升 `@n` 或提示迁移。  
7. 产品发版用 Tagma `0.x`；配方版本用 `@n`，不与云模型「V3」抢心智。

错误示例（禁止作 API id）：`tagma/抖音研报`。  
正确：`public_id: "tagma/douyin-report"` + `display_name: "抖音研报"`。

### 7.3 组合配方 schema（最小）

```json
{
  "id": "composite:u_douyin_report",
  "public_id": "tagma/douyin-report",
  "display_name": "抖音研报",
  "version": 1,
  "brain": {
    "mode": "first_cloud | explicit | local_brain_pack",
    "provider_model": null
  },
  "members": [
    { "pack_id": "pack:reachflow", "role": "crawl" },
    { "pack_id": "pack:ffmpeg-edit", "role": "edit" }
  ],
  "routing": {
    "strategy": "intent | manual | sequential",
    "notes": "可选：意图规则引用"
  },
  "created_at": "2026-10-15T00:00:00+08:00"
}
```

**brain.mode（v0）：**

| 模式 | 含义 |
|------|------|
| `first_cloud`（推荐默认） | 不选手动 LLM 时，按 **全局供应商排序**（供应商页的跨 App 默认渠道序）取第一个「已启用且最近检测为连通」的云模型；若无全局序，则用「当前写入本机网关的默认 App 配置」里同样规则的第一个。若无任何可用云渠道 → **明确错误**（禁止静默失败）；可提示去配供应商或安装 Local Brain，**不**暗装大模型。 |
| `explicit` | 用户指定某个云 `provider_model`。 |
| `local_brain_pack` | 使用已安装的 `tagma/local-brain` 队员。 |

**`none`（无对话脑）：v0 不开放。** 字段不进入 v0 合法枚举。工具-only 流水线若未来需要，于运行时契约稳定后单独立项，再写入 schema。

## 8. Pack manifest 最小字段

```json
{
  "id": "pack:reachflow",
  "name": "ReachFlow",
  "version": "0.1.0",
  "kind": "mcp_runtime | binary_pipeline | python_worker | composite_helper",
  "public_model_id": "tagma/reachflow",
  "entry": { "type": "sidecar | mcp | wasm", "command": "…", "args": [] },
  "platforms": ["windows-x64", "darwin-arm64", "linux-x64"],
  "resources": { "download_mb": 80, "needs_gpu": false },
  "openai": {
    "expose_as_model": true,
    "tools": true
  },
  "permissions": {
    "network": true,
    "filesystem": ["workspace", "downloads"],
    "shell": false
  },
  "healthcheck": { "path": "/health", "timeout_ms": 5000 },
  "sku": "official | community"
}
```

安装路径约定（实现可调）：`{app_data}/packs/<id>/<version>/`。  
校验：签名或 checksum（**交付阶段 P2** 起对官方源强制）。  
进程：队员**一律**子进程/sidecar 隔离；壳在队员崩溃后仍可改 Provider。  
（此处 sidecar = 队员进程；网关本身已冻结为独立 sidecar，见 §5.3——勿混称。）

**`kind` 选型偏好（插件期执行纪律，不改地基范围）：**

| kind | 适用 | 偏好 |
|------|------|------|
| `binary_pipeline` | TTS / ASR / 音视频管线等重推理 | **优先**：预编译 native（**含 C++** 引擎，如 audio.cpp / YoVoice 路线）；用户无装 Python |
| `mcp_runtime` | 已是 MCP 的队员、桥接样板 | ReachFlow 等可走此路 |
| `python_worker` | 生态绑死 Python 的队员（如部分爬虫） | **允许**，但须自带/打包解释器或明确环境；**非**面向终端用户的音频类首选 |
| `composite_helper` | 配方辅助 | 轻逻辑 |

参考：**YoVoice（leemysw/yovoice）** = 音频类队员的打包/推理模式参考，**不是**把 Tagma 核心改写成 C++ 的理由。

## 10. 用量与渠道（New API 味 · 个人版从简）

### 10.1 本机网关 API Key（个人版）

| 模式 | 行为 |
|------|------|
| **默认：鉴权关闭** | localhost 信任。兼容「客户端必须带 Key」的 Agent：请求里的 Key **可为任意非空字符串**（如 `tagma`），网关**不校验**对错，只要求非空（若客户端连空 Key 都不发，则亦不强制）。 |

禁止表述成「Key 填任意且永远校验通过」——那只适用于**鉴权关闭**时的占位兼容。

**个人版 · 交付阶段 P1 必有：**

- 按 Provider / 模型 / 小队 id 记请求次数、token（能拿到则记）、错误率

**个人版不做（推后）：** 完整计费 SaaS、多租户发票、复杂充值。

**服务器版（交付阶段 P4）：** 按 API Key / 用户记账；渠道故障切换与 New API 同级能力再评估。

## 附录 A：成功标准（对外可称「网关可用」= 交付阶段 P1 切片）

1. 任意支持 OpenAI 兼容的 Agent 指向 Tagma 后能完成一轮流式对话（**不依赖**内置对话 UI）。

## 附录 B：风险与缓解

| 风险 | 缓解 |
